# USB LinkMic：重建行为规格

日期：2026-10-16（Asia/Shanghai）  
状态：第一阶段分析产物，供第二阶段使用；尚未实现、尚未经用户逐项确认。  
范围：完整保留三种核心用途，并补全安装、授权、状态和恢复流程。实现语言、模块结构、UI 设计和内部协议不在本阶段拍板。

本文件描述用户行为、系统约束和验收条件，不依赖旧版源码结构。严格隔离的实现者只接收本规格及用户后续决策；旧版代码和拆解证据不作为其输入。

## 1. 产品目标和边界

用户安装 Mac 应用后，能够在界面引导下完成手机连接与必要授权，使用手机拾音、手机供网或 Mac 反向供网，并能明确知道当前阶段、失败原因和下一步。

| 用途 | 输入 | 用户获得的结果 |
| --- | --- | --- |
| 手机麦克风给 Mac | 手机麦克风声音 | Mac 耳机/扬声器可试听，或会议/录音软件能选择对应音频输入 |
| 手机网络给 Mac | 手机可用网络 | Mac 通过 USB 使用手机网络 |
| Mac 网络给手机 | Mac 可用网络 | 手机应用经 USB 使用 Mac 网络 |

当前平台范围以 macOS 26 和 Android 8+ 为候选基线；特定音频格式与手机供网可能需要更高版本或设备能力，应声明支持条件。Apple Silicon 为现有主要目标，Intel 和降低 macOS 最低版本属于待决定项。

不默认新增：云账号、云同步、转写、文件录音、主动降噪、UDP、独立 USB 音频设备模式、局域网自动发现、静默授权、自动安装系统音频驱动。

## 3. 用户操作和准备流程

### 3.1 一次启动的共同前置流程

用户选择功能并点击启动后，系统依次确定：

1. 目标设备或 Wi-Fi 连接目标是否明确。
2. 需要 USB 时设备是否连接并完成 USB 调试授权。
3. 需要配套 App 时是否已安装、兼容。
4. 未安装则安装内置配套包，显示进度，等待用户确认手机安装。
5. 需要权限时触发对应手机系统请求，显示等待对象与可执行操作。
6. 前置条件完成后继续用户原本发起的任务。

适用前置条件由功能决定：Wi-Fi 音频不应强制连接 USB；手机供网不应要求麦克风权限；反向供网不应要求录音授权。

在检查、安装、系统授权和等待用户时，必须显示准备状态。不能显示“麦克风运行中”“已连接网络”或“正在传输”。重复点击应复用同一任务，停止/取消应使迟到结果无法再次启动服务。

### 3.2 安装和版本处理

- Mac 安装包包含兼容的手机安装包和所需本地工具。
- 已安装且兼容时不重复安装。兼容性按两端协议/能力判断，不能只比较显示版本号。
- 不兼容时解释需要更新什么，执行结果可复查。
- 手机拒绝安装、签名冲突、禁止降级、设备断线、安装包缺失是不同错误。
- 签名冲突不应通过自动卸载处理；保护用户已有 App 数据。
- 手机明确拒绝时停止自动重试，允许用户处理后主动再试。
- 所有需要配套 App 的功能使用一致的准备体验。

### 3.3 权限与用户等待

| 权限/授权 | 触发时机 | 拒绝后的行为 |
| --- | --- | --- |
| USB 调试 | 首次连接或信任失效 | 告知需要在手机确认；不尝试绕过 |
| USB 安装 | 安装手机配套 App 时 | 说明被拒绝或受系统限制；用户处理后可重试 |
| 麦克风 | 用户首次启动拾音 | 请求系统权限；获准后继续原任务；拒绝后不采音 |
| 通知 | 需要后台服务提示时，按设备系统要求处理 | 不把“拒绝通知”显示成“没有录音权限”；解释实际影响 |
| VPN | 用户首次启用 Mac 给手机供网 | 手机系统请求；获准后继续，拒绝则清理已准备资源 |
| 虚拟声卡系统安装 | 选择给其他软件当麦克风且驱动缺失时 | 提供官方安装入口和重新检测，不自动降低系统保护 |

“首次未请求”“已拒绝可再请求”“需要去系统设置”应使用不同提示。只打开手机主页不算请求权限成功。等待用户期间不启动音频首包计时；网络授权等待也不能使用过短的后台连接超时。

## 4. 设备、任务与结果状态

应分别表达以下事实，而不是共用一个“就绪”开关：

| 对象 | 用户可见状态 |
| --- | --- |
| 设备 | 未连接、未授权、在线、离线、重新识别中 |
| 配套 App | 未安装、安装中、待确认安装、兼容、不兼容、检查失败 |
| 权限 | 未请求、等待确认、已允许、已拒绝、需系统设置 |
| 模块任务 | 已停止、检查中、准备中、等待用户、连接中、运行、停止中、失败 |
| 音频 | 未连接、握手中、等首包、有效音频传输、输入中断、故障 |
| 供网 | 链路准备、获得地址/建立隧道、出口验证、可用、无外网、故障 |

音频全零但帧有效属于正在传输的静音；没有帧属于无输入。服务绑定和进程存在不等于正在采音。VPN 图标和 IP 地址不等于已验证可上网。

恢复连接时应重新确认设备和任务归属。多手机场景不能因设备顺序变化而把操作发给另一台手机。

## 5. 音频功能

### 5.1 USB 麦克风

用户在 Mac 开始/停止。手机显示正在采音、是否由 Mac 控制，以及实际生效参数。开始后应验证真实音频，而不只验证控制命令下发成功。

停止应关闭采音、传输、接收和本次创建的转发资源。录音硬件不可用、被占用、不支持参数、端口占用、断线和首包超时需要不同诊断。

### 5.2 Wi-Fi 麦克风

Mac 显示可连接的本地地址和端口；手机可以编辑并记忆目标。用户先启动 Mac 接收，再在手机启动连接。断线时双方状态应一致，并提供重试。

网卡选择、监听范围、连接者身份和允许的发送端数量应有明确规则。第二台连接不能无提示地混入或替换当前音频。跨不可信网络不属于默认支持场景。

### 5.3 音频参数

- 缺省建议：44100 Hz、单声道、i16、普通麦克风源。这是重建起点，不是已完成硬件性能验证。
- 保留采样率、声道、PCM 格式和录音源配置能力。
- UI、校验、发送端、接收端共享同一组能力定义；展示实际生效值。
- 选项必须满足两端系统/API/硬件条件。不支持时应明确拒绝或提出可确认的替代方案，不悄悄退回另一种采样率。
- 立体声不代表手机一定有独立双通道麦克风；以实际采集能力为准。
- 修改采集或连接参数时，先结束旧会话再建立新会话；修改增益/静音应即时应用。

高采样率和高位深属于功能保留范围中的候选能力，具体列表要在第二阶段依据能力探测确认，不能照抄旧版不一致的选项。

### 5.4 输出与用途

| 用途 | 行为 | 完成条件 |
| --- | --- | --- |
| 本机试听 | 输出到用户选定的耳机/扬声器/系统默认设备 | 指定设备有真实声音；停止后不再输出 |
| 给其他软件当麦克风 | 将声音送到兼容虚拟音频设备，指导外部软件选择它 | 外部软件输入电平和实际录音能够证明收到手机声音 |

支持输出设备刷新、稳定标识持久化、热插拔、增益和静音。用户显式选定的输出离线时，应停止输出并提示，不得自动改为扬声器。

虚拟声卡缺失时显示安装指引；App 无法自动判断所有会议软件已选对输入，必须让用户确认或用实际录音证明。Mac 输出静音不意味着手机停止录音，应明确标识。

### 5.5 电平和趋势

电平与波形只来源于真实接收样本。开始前、断线后和错误时不能继续显示模拟传输。显示平滑不能掩盖输入中断。

## 6. 两个供网方向

### 6.1 手机网络给 Mac

1. 确认 USB 设备、系统能力、配套 App 和所需授权。
2. 记录要改变的 USB 功能及 Mac 网络服务状态。
3. 建立手机有线共享，允许正常的 USB 重枚举，向用户解释等待阶段。
4. 确认相关接口、地址、网关及路由。
5. 验证通过手机出口的实际网络请求，分别展示链路状态与网络可用性。
6. 停止、失败或取消时恢复所拥有的改动，并验证 Mac 原有出口恢复。

某些 ROM 不具备该能力时，显示“不支持/被系统限制”，说明判断依据，不显示通用成功。上游没有互联网与 USB 链路失败要分开。

### 6.2 Mac 网络给手机

1. 确认 Mac 当前可用上网出口。
2. 准备本地转发与手机连接，等待手机 VPN 授权。
3. 确认转发服务、手机 VPN、隧道状态。
4. 验证手机应用的 DNS 和实际请求经 Mac 出口成功。
5. 支持 IPv4 DNS 和 CIDR 路由设置。
6. 停止、失败、取消时清理 VPN、隧道和本次启动的本地进程。

它是网络共享，不承诺匿名、绕过网络策略、额外端到端加密或所有 IP 协议支持。IPv6、ICMP、IPv6-only 网络等支持范围须单列确认，不从“VPN 已连接”推定支持。

### 6.3 互斥与并用

两个供网方向互斥。切换需要完成原方向停止和恢复再启动新方向，失败不能把旧方向标记成仍正常。

音频与每个网络方向能否稳定并用，需要组合验收。USB 重枚举时应解释影响，若要自动恢复必须保证用户没有主动取消、设备未被替换，且权限仍有效。

## 7. 手机配套界面、设置与诊断

手机显示三项模块状态、实际录音参数和音频趋势。ADB 模式由 Mac 控制，Wi-Fi 模式提供本机开关。网络卡片显示状态和需要在 Mac/手机执行的下一步。保留日志、清空及刷新状态。后台录音和VPN按系统要求显示可识别的前台通知；当前VPN通知的停止入口应保留。录音通知是否新增停止按钮属于体验改进，应明确由谁停止以及Mac如何同步状态。

Mac 提供设备页、日志页、首次向导、设置与全部停止。设置支持编辑草稿、保存、取消、参数校验和持久化，明确哪些改动会中断连接。

日志应包含：任务/阶段、目标设备的可脱敏标识、动作、结果、耗时、失败类型及用户可执行的下一步。诊断导出遮盖序列号、IP 和用户目录；不得承诺它能消除所有任意文本中的敏感信息。日志窗口与导出保留策略要明确。

Mac 常用快捷操作保留刷新、设置和全部停止。明暗外观跟随系统，窄窗口仍可完成核心任务。

## 8. 清理、恢复和权限边界

每个任务应知道自己创建/修改了哪些资源。停止与退出不得清除其他设备的转发、无关网络服务、用户文件、其他 VPN 或外部应用设置。

退出清理有时间上限。未完成的清理应记录并在下次启动处理，向用户显示恢复结果。崩溃后不能假设旧会话仍在正常运行，也不能无条件自动开始录音。

普通第三方 Android App 不应能绕过用户授权远程启动采音或供网；诊断接口只读并受适当访问控制。用户授权不能通过脚本伪造为已同意。

## 10. 性能与质量验收如何确定

本阶段没有测得延迟、功耗、内存、持续稳定时间或供网速率，因此不给出虚假的性能基准。

第二阶段必须记录端到端音频延迟、持续音频中的中断/欠载、后台资源占用、断连恢复耗时、退出耗时和供网吞吐。目标值在初始真实硬件基线后确定。旧版10秒首包/2秒中断可作比较数据，不自动成为新版设计要求。

单元测试验证状态和接口；集成测试验证进程与连接；真实设备验证权限、音频、供网；最终发行包验证用户可安装使用。模拟音频、假 ADB、进程存活和编译通过各自只证明相应层级。
