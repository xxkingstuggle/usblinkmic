# 工作原理

USB LinkMic 把 Android 和 macOS 已有的音频、USB 网络及 VPN 能力连接起来。Mac 负责设备选择、任务控制和状态展示，Android 负责录音与手机侧网络会话。

## 手机麦克风

Android 通过 AudioRecord 采集 PCM 音频，将音频帧传到 Mac。Mac 按协商得到的采样格式接收、计算电平，并输出到选定的音频设备。

USB 连接通过 ADB 建立 socket 通道。Wi-Fi 连接使用局域网地址、端口和配对码，采集与播放流程相同。Wi-Fi 音频目前没有传输加密。

在 Mac 上有两种输出方式。

|用途|音频路径|
|---|---|
|本机试听|手机 → USB 或 Wi-Fi → USB LinkMic → 耳机或扬声器|
|虚拟麦克风|手机 → USB 或 Wi-Fi → USB LinkMic → BlackHole → 会议、录音或直播软件|

BlackHole 提供可供其他软件选择的音频输入设备，需要单独安装。USB LinkMic 本身不把手机模拟为原生 USB 声卡。

## 手机网络给 Mac

Android 切换到 USB NCM 模式，通过系统网络共享能力将手机网络提供给 Mac。Mac 等待 USB 重新枚举，识别对应的网络服务，并检查链路和地址是否就绪。

这条路径依赖手机 ROM 对 USB NCM 和共享接口的支持。Mac 的实际网络出口由系统网络服务决定，Wi-Fi 与 USB 网络同时存在时，可以在系统设置中调整优先顺序。

## Mac 网络给手机

Android 使用系统 VPN 接口接收网络数据，经 USB 送到 Mac 上的 Gnirehtet relay，由 Mac 转发请求并返回响应。当前支持 IPv4 TCP 和 UDP，无需手机 root。

这里的 VPN 用于把流量交给本地转发程序，不提供额外的匿名访问或加密服务。

## 连接与停止

音频、手机供网和反向供网分别维护会话状态。两个供网方向互斥，切换前需要完成上一项的清理。

网络的「已连接」表示链路和转发通道就绪。应用不会因为单个公网网站访问失败而主动拆除连接；设备断开、relay 退出或 VPN 被系统收回时，会更新对应状态。

停止时，会话关闭自己创建的转发与进程，并恢复本次修改的 USB 设置。对已有共享的借用会保留原状态。恢复失败会留下错误和恢复记录，供下次连接时处理。

协议、状态字段和资源归属见 [contracts](../contracts/README.md)。
