# 安装方案（尚未执行，等待用户确认）
这是4.0.0审阅构建，协议4，不兼容旧配套。当前不是全面验收通过的正式发布。

1. 先保留现有Mac App、手机App及数据；不运行自动卸载。不在批准前覆盖 `/Applications/USB LinkMic.app`。
2. 获准后先将DMG内应用复制到用户指定的隔离位置，用内置ADB/配套APK/Java运行时测试；普通使用不需要Xcode/JDK/Android SDK。
3. Mac当前仅ad-hoc签名，未Developer ID签名或Apple公证。首次打开可能被Gatekeeper阻止；不提供关闭系统保护或脚本绕过的自动操作。正式分发签名与公证仍是T24缺口。
4. USB连接：在手机主动启用开发者选项/USB调试并确认信任。Mac选择目标手机和用途后启动；缺配套时安装内置APK；安装系统限制、签名冲突或降级均明确停止，不自动卸载。现有配套同协议时不重装。
5. 在手机确认本次会话。首次录音出现系统麦克风请求，通知请求单独处理。允许后继续；拒绝后不采音。永久拒绝打开App系统设置处理。
6. 本机试听选择输出；其他软件输入需用户自行从BlackHole官方入口安装驱动，选择其输出，并在会议/录音软件选择BlackHole输入，以真实录音证明收到手机声音。
7. Wi-Fi：在Mac设置监听明确的局域网IPv4（默认127.0.0.1仅USB），启动接收；将Mac地址、端口和32位配对码填入手机。仅可信局域网，无额外加密，仅一个发送端。停止在任一端执行后应同步断开。
8. 手机供Mac：需ROM允许CDC-NCM，手机系统共享页仍需用户启用；Mac验证绑定新USB接口的HTTPS请求。系统默认出口必须选中USB才报告可用；必要时用户在Mac网络设置调整服务顺序。本应用不擅自改写其他服务或路由。已由其他任务开启的NCM共享不会被接管。
9. Mac供手机：确认Mac出口，手机确认VPN系统请求；手机DNS和HTTPS探测经VPN成功后才报告可用。仅IPv4 TCP/UDP；不承诺ICMP/IPv6/IPv6-only网络。
10. 全部停止与退出清理只作用于本次资源；失败保留恢复日志，下次启动清理，不自动录音。

## 待用户批准后的验收
按 docs/manual-acceptance.md 的T01—T24进行。特别检查首次系统弹窗、拒绝与永久拒绝、通知差异、真实声音/外部软件输入、两方向网络请求/恢复、插拔与组合、性能基线。
