# USB LinkMic 4.0.3 安装与使用

这是待用户测试的修复构建，协议4、配套运行时修订403。编译和打包不代表音频/网络功能已验证；本轮测试由用户自行执行。

1. Mac要求macOS26及Apple Silicon。将包内USB LinkMic.app放入应用程序目录，保留原应用数据；不需要Xcode、JDK或Android SDK。旧发行包可以保留用于回退。
2. Mac当前为ad-hoc签名，尚无Developer ID或公证；首次Gatekeeper体验仍未验收。不要通过脚本关闭系统保护。
3. Android配套支持Android8+的音频功能；手机给Mac的NCM自动共享路径需要Android11+及相应ROM能力。手机连接时自行启用USB调试并确认信任。
4. Mac开始功能前检查协议和runtimeRevision；低于403的旧配套会用包内APK升级，保留应用数据。手机要求确认安装时由用户操作；签名冲突、系统禁止或降级会停止，不自动卸载、不自动授予权限。
5. 手机确认本次会话。首次录音出现系统录音权限请求；通知权限独立。允许后继续原请求；拒绝不采音，永久拒绝到应用系统设置处理。
6. 本机试听使用系统默认或明确选择的输出。虚拟麦克风使用BlackHole，其他软件选择对应BlackHole输入。选择虚拟用途时，如果只有一个BlackHole会自动选中；未找到时需先安装，不能只改用途而继续向扬声器输出。真实声音由用户试听/录音验证。
7. Wi-Fi在Mac设置明确的局域网IPv4（127.0.0.1只适合USB），将地址、端口和配对码填入手机。只在可信局域网使用，当前配对码不提供传输加密。
8. 手机给Mac供网：Mac开始→手机确认本次请求→Mac切换USB到NCM并等待重新连接→配套shell助手调用系统以太网共享→等待DHCP与实际出口请求。此流程不再要求同时去系统共享页切换USB热点，以免系统改成其他USB协议。USB重枚举前会停止既有USB音频，共享准备好后可重新开始麦克风，不自动恢复采音。
9. 应用不修改其他Mac网络服务顺序或全局路由。如果USB接口请求成功但系统默认出口仍走其他接口，会提示到Mac网络设置检查USB服务/服务顺序，不假报整机已经使用手机网络。不接管已由用户/其他软件开启的NCM共享。
10. Mac给手机供网仍需手机VPN系统授权，以手机真实DNS/HTTPS结果判断状态；仅IPv4 TCP/UDP。两种供网方向互斥。
11. 全部停止/退出按本次资源归属清理并恢复USB功能；恢复失败保留journal，下次启动继续恢复，不启动录音。手机断开时需接回同一设备才能完成USB恢复。

## 本轮自行测试

重点检查试听和BlackHole持续传输、停止重连、手机共享的USB重枚举/实际联网/停止恢复，以及先供网再开始麦克风。完整场景保持docs/manual-acceptance.md的T01—T24；本轮没有把它们记为通过。

本地脱敏日志位于`~/Library/Application Support/USBLinkMic-v4/diagnostics.log`，最多256KiB，不存储PCM。界面日志可导出供分析。

Android安装身份为com.zjx.usblinkmic；后续升级保留源码目录未跟踪的.tools/signing私钥，不把签名材料放进发行包或Git。包内APK/工具指纹见manifest.json与SHA256SUMS.txt。
