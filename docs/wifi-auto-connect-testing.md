# USBLinkMic 纯 Wi-Fi 自动连接：真机测试与验收指南

本文档提供版本 **4.0.17**（Wi-Fi Revision 1，审查返工第三轮）纯 Wi-Fi 自动连接功能的真机测试与验收说明。

> [!IMPORTANT]
> **开发安全与隔离承诺**：
> 候选尚未安装或启动。主代理已核对现用 Mac 应用的主程序、Info.plist 和内置 APK 指纹未变，现用进程仍在运行。以下步骤由用户在准备测试时自行操作；普通 Wi-Fi、手机热点、后台持续采音和 BlackHole 实际输入仍待真机验收。
>
> **注意单实例运行**：准备测试时，请先正常退出现用 USB LinkMic。直接从候选目录运行新版，不要将它拖入 `/Applications` 覆盖旧版，也不要同时运行两份 Mac App。两版默认共用 `~/Library/Application Support/USBLinkMic-v4/`，先备份该状态目录。

## 2. 测试前准备与备份

### 2.1 备份现有运行环境
先正常退出旧 Mac App，再将旧应用和整个 `~/Library/Application Support/USBLinkMic-v4/` 状态目录复制到自己选择的、尚不存在的备份目录。保留原目录，不清空、不删除。候选运行后产生的新信任记录不妨碍重新使用旧 Mac App。

如果后续需要回滚到旧版本：
1. **Mac 端备份**：
   - 现安装应用位于 `/Applications/USB LinkMic.app`。如需备份，执行：
     ```bash
     cp -R "/Applications/USB LinkMic.app" "$HOME/Desktop/USB LinkMic-backup.app"
     ```
2. **Android 端备份**：
   - 当前手机上安装的原版 APK 在 Mac 备份位置：
     `/Applications/USB LinkMic.app/Contents/Resources/companion.apk`
     这只是旧安装包，不包含手机的设置或绑定数据；不要为了测试先卸载手机 App。
     （SHA-256: `2643069518c0d84916890887cbdb9aee0dcc25ea58dc53e43f455fc089d9b4bb`）

### 2.2 测试环境网络配置要求
支持以下两种可互通网络环境之一：
- **场景 A（推荐）：家庭/办公普通 Wi-Fi**：手机与 Mac 连接到同一个无线路由器，且路由器未开启“AP 隔离”或“访客模式”。
- **场景 B：Android 手机热点**：Android 手机开启便携式热点，Mac 搜索并加入该热点 Wi-Fi。

## 3. 真机测试用例与验收步骤

### 用例 1：首次配对与安全授权（6 位码比对）
1. **安装并打开**：
   - 用户准备测试后，使用相同签名的 `USBLinkMic-4.0.17.apk` 覆盖升级手机 App 并打开；不要先卸载。若通过 USB 安装，安装完成后拔线再开始验收。
   - 解压 macOS ZIP 或挂载 `USBLinkMic-4.0.17.dmg`，从独立目录启动候选 `USB LinkMic.app`。
   - **完全拔掉 USB 数据线**，确认 `adb devices` 没有任何连接。
2. **观察自动发现与选择设备**：
   - 确认 Android 界面上的“局域网自动连接”处于开启状态。
   - 在“发现的 Mac”列表中看到 Mac 广播的 `_usblinkmic._tcp` 服务条目后，点击目标 Mac 的“配对并信任”。
3. **安全确认交互**：
   - 手机端界面显示正在配对的 Mac 名称与 **6 位数字校验码**，提示“请在 Mac 上核对验证码并确认配对”。
   - Mac 端弹出“请求绑定 Wi-Fi 麦克风”横幅/弹窗，显示待配对手机名称与相同的 **6 位数字校验码**。
   - **核对两端 6 位数字必须完全一致**后，在 Mac 端点击“**允许并绑定**”。
4. **通过判定**：
   - 两端保存设备信任记录，之后不再要求重复配对；
   - 手机端自动启动前台录音服务并向 Mac 的音频端口建立音频连接开始传输；
   - Mac 麦克风主体显示传输中，帧数稳定增长，电平表随手机声音变化。侧栏设备选择器仍用于 ADB/USB 设备，拔线时可能显示“等待手机连接”；Wi-Fi 验收以主体和可信设备状态为准。
   - 若使用虚拟麦克风，在录音或会议软件里明确选择 `BlackHole 2ch` 输入，再对着手机讲话确认输入有变化，避免误把 Mac 内置麦克风当作结果。

## 4. 日常使用与自愈验收

> [!NOTE]
> 以下用例中所提及的 10 秒建连或 20 秒断开检测均为无严重无线信道干扰下的**设计目标指标**，实际耗时可能因局域网信道拥塞或 Android 系统 NSD 检索调度略有波动。

### 用例 2：免配置自动连接（日常使用体验）
1. **前置条件**：已通过【用例 1】完成首次信任配对。
2. **测试操作**：
   - 将两端完全退出：Mac 正常退出应用；Android 在系统“应用信息”中强行停止后再打开，不清除数据。只划掉后台任务卡片不能证明前台采音服务已退出。
   - 拔出 USB 数据线（确保处于纯无线状态）。
   - 打开手机 App，再打开 Mac App（或先开 Mac 再开手机，分别测试两次）。
3. **通过判定**：
   - 无需再次确认配对码、无需输入 IP 地址、无需任何手动点击；
   - 两端自动完成服务发现、互相鉴权、准备接收器并开始拾音传输（设计目标 10 秒内）；
   - Mac 菜单栏和主界面正确显示手机设备名与音频电平。

---

### 用例 3：手动停止与防意外自动恢复
1. **测试操作**：
   - 在正在无线采音的状态下，在手机端或 Mac 端点击“停止”。
   - 观察 60 秒，期间随意切换 App 界面、锁屏、点亮屏幕。
2. **通过判定**：
   - 两端停止采音并保持在就绪/暂停状态；
   - 自动连接机制不应覆盖用户的“停止”意图重新唤醒录音；
   - 当用户再次主动点击“开始拾音”时，能够正常恢复无线录音。

---

### 用例 4：短断网与 IP 漂移自愈
1. **测试操作**：
   - 在正常无线采音时，将手机 Wi-Fi 开关关闭 5 秒，然后再重新打开；
   - 或者在路由器后台为手机/Mac 重新分配不同 IP，或关闭热点重开。
2. **通过判定**：
   - 断网瞬间两端及时感知并清理旧连接；
   - 连网恢复后，NSD 发现解析当前端点，双方使用保存的信任记录恢复音频流，无需手动输入 IP。
   - 已绑定后也应清空手机手动连接栏里的旧 IP 再重复一次，确认没有依赖旧地址。只有确认前后 IP 不同，才能把“IP 变化恢复”标为通过。

---

### 用例 5：热点模式实测
1. **测试操作**：
   - 手机打开移动热点，Mac 连接手机热点。
   - 启动两端 App，验证在 Android 热点网络拓扑下，系统 NSD 与 Bonjour 能否顺利发现和互联。
2. **通过判定**：
   - 系统 NSD 广播与解析顺畅，能像普通 Wi-Fi 一样顺利完成发现并稳定传输音频。

## 5. 故障排查与诊断导出

- **Mac 端诊断与设备管理**：
  - 在 Mac App 的“**设备与权限**”页面，可查看“已信任并允许自动连接的手机”列表，点击“解除信任”可撤销指定手机授权。
  - 在“**诊断日志**”页面点击“导出诊断日志”或“拷贝日志”，可查看 `[wifi/auto]` 模块的连接与认证事件。反馈时使用脱敏诊断导出，不附带 `wifi-trust.json` 或应用私有设置文件。
- **Android 端诊断与设备管理**：
  - 在手机 App 设置页面的“已信任的 Mac”列表中点击“解除信任”撤销信任记录。
  - 在手机 App 界面底部查看诊断日志，确认 NSD 发现、握手与传输事件。

## 6. 回滚指南

如需彻底回滚到测试前状态：
1. **Mac 端**：
   - 退出 4.0.17 版本的候选应用；
   - 直接重新打开原 `/Applications/USB LinkMic.app`；测试过程没有覆盖它，通常无需恢复应用。
   - 保留状态和信任记录，不需要删除 `wifi-trust.json`。确需还原设置时，先备份候选运行后的状态，再由用户恢复之前保存的状态目录。
2. **Android 端**：
   - **免卸载恢复（推荐，保留配置）**：直接在应用内设置页关闭“Wi-Fi 自动连接”开关后可与旧 Mac 版继续使用手动 Wi-Fi 或原 USB 工作流，无须卸载应用；
   - **版本降级**：若需要降级回原版 `companion.apk`，由于 Android 系统的签名和版本保护机制，降级安装前通常需要先卸载当前应用（请注意：卸载将清除应用本地所有数据与权限授权），然后重新安装原版 `companion.apk`。


## 7. 测试结果记录

每种网络分别记录：两端版本、Mac/手机启动顺序、发现是否出现、配对是否成功、首次真实帧耗时、重连耗时、持续传输至少 5 分钟、锁屏结果、停止后 60 秒结果及 BlackHole 实际输入结果。失败时记录两端界面状态并导出脱敏日志；发现成功、TCP 接通或电平曾跳动不单独等于整项通过。

本次主代理复核通过的是 39 项指定 Mac 隔离测试和 19 项 Android 自动连接测试，以及构建产物的静态检查；不代表完整测试套件或真实设备场景通过。
